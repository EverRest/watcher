# Audit 2026-10-23: security, privacy, cost, reliability, architecture

Six read-only reviews of `everrest/watcher` at commit `d82ac6a` (security, adversarial privacy, token efficiency, reliability,
architecture, and a survey of the first three target services). Probe scripts live outside the repo. Items marked **✔**
were re-checked by hand against the code or reproduced; the others carry the reviewer's own CONFIRMED/PLAUSIBLE label.

**Status (same day): all ten P0 items are fixed** with failing tests first, in commits `9266039` (P0-1 to P0-7, P0-9,
P0-10 and P0-8, which landed in the same commit) and verified by the full suite (764 tests) on PHP 8.5. Decisions taken
while fixing: undeclared call targets in the digest are now a **count, not names** (naming them leaked tenant and person
names), and a host is kept in templates only when it belongs to a **declared** dependency. P1 items below are open.
Feature proposals became specs 002-006 (`docs/roadmap.md`).

**Original verdict (before the fixes): do not run T114 on real logs yet.** Two guarantees the docs make are currently false (privacy for JSON logs
and cluster hosts; the daily budget on Redis), and one ordinary input crashes about one run in six. All P0 items are
small, local fixes; together roughly one day of TDD work.

## P1: before production

**Privacy**
- Frames with a name and no dot (`/srv/olena_shevchenko/a.php:4`, `/home/annakowalski/x.php`) reach the model and Slack code links. Keep frames only under a `repo.path_map` prefix (or a configured list of path roots).
- A name repeated by a retry/worker loop (3 identical events from one person) survives variation masking and also enters the log-link literal. Remove the literal from links (or cut it before the first placeholder); optional rule for capitalised word pairs mid-sentence; document the retry-loop case.
- Invisible/format Unicode (`​`, RTL marks, fullwidth `@`) defeats the email rule: NFKC-normalise and strip `\p{Cf}` before the rules.
- Letter-heavy secrets (base64 session ids, keys without digits) survive: mask high-entropy tokens of 20+ characters.
- `docs/privacy.md` is wrong in two places: withholding works **per cluster**, not per group (a one-off group can get a fully masked `<*> <*> <*>` template from its cluster); the second scan nests placeholders (`<URL:<HOST:x>>`). Also its claim about watch-rule regexes as backend filters (see P0-8).

**Reliability and failure semantics**
- A failed digest delivery loses the finding: verdicts are cached before `send`, so the retry in the same hour is `quiet` (exit 0). Buffer verdict writes and flush after delivery; send a failure notice when the notice destination differs.
- Every DST change re-baselines: `Window::endingAt` subtracts PT24H in UTC, so the window start no longer matches the previous end key (also a 1 h gap/overlap; on fall-back a `03:xx` run is due twice). Compute start as local `run_at` minus one calendar day and add a `snap:<svc>:last` pointer.
- One transient failure costs two days (no snapshot, next day re-baselines). Loki has no retries; Datadog retries only 429. Add 3 tries with backoff on 5xx/connect errors and compare against the newest available snapshot, labelled.
- Truncation flag is lost for the level-anomaly pass (`Watcher.php:264` reads `lastReadTruncated()` once); "events read" excludes muted events. Replace the hidden-state method with the generator return value.
- PDO connect failure crashes the CLI with a stack trace (exit 255, no notice) and on PHP 8.1 can print part of the DSN/password (`Factory.php:65`). Catch and rethrow `InvalidConfig('state.pdo: cannot connect')` unchained.
- Redis connect failure is reported as invalid config (exit 2) on every hourly trigger, even when not due (`Factory.php:87`): connect lazily after the gate; report as `failed`.
- MySQL `TEXT` (64 KB) overflows at ~3.5k groups per snapshot (`PdoStateStore.php:43`): `MEDIUMTEXT`.
- Laravel provider passes no logger (`WatcherServiceProvider.php:22`): inject `LoggerInterface`.
- Datadog page limit 1000 (API allows 5000); 429 waits up to 60 s x 3 per page; no total wall-time budget. Lock is not renewed; `activeDeadlineSeconds` = `lock_ttl` in the docs means a slow run is killed silently.
- Reducer memory: 200k events / 100k distinct templates = 374 MB (over the 128 MB CLI default): fatal, no notice, lock until TTL. Cap clusters; set `memory_limit` in the docs.
- File store never purges unread expired files; `.lock` sidecars accumulate; `file_put_contents` returning `false` is ignored and an empty temp file can replace a good record on a full disk.

**Security**
- Prompt injection can get an error family triaged as `noise`, cached for 30 days: never cache `noise` for `error`+ or watch-rule groups (or short TTL).
- Regex failures in watch/mute matchers (`false` from `preg_match`) are silent "no match": surface them.
- The SDK falls back to `ANTHROPIC_BASE_URL` from the environment when no base URL is passed: pin `https://api.anthropic.com` (configurable explicitly).
- Secrets are public array properties on `WatchConfig` (visible to `dd()`, Ignition/Flare argument capture): hide them like `Destination` does.
- State values are trusted for types (`atCount`, counts): validate on read.

## Token efficiency and cost (measured)

Realistic input: 60 candidate groups, 3 frames each, 5 dependencies x 5 top errors.

| Payload | Bytes | Tokens (~b/4) |
|---|---|---|
| Triage, 60 groups | 23,222 | ~5.8k |
| Analysis, 10 groups + 5 deps | 8,088 | ~2.0k |
| Escalation, 1 group + 5 deps | 4,518 | ~1.1k |
| Prompts triage / analyze | 1,727 / 3,399 | ~430 / ~850 |

Estimated cost per run with tier prices of the time ($0.10/$0.50, $2/$10, $4/$20 per MTok): **$0.04-0.16**, of which
**escalation is 60-75%**; triage input is under 2%.

Wins, in order of value:
1. **Escalation policy** (escalate only `critical`, or cap 1, or lower effort): 30-60% of spend.
2. **Do not send all dependencies to escalation** (`ModelRouter::remap` keeps all 5): 60-75% less escalation input.
3. **Payload trim**: drop `first`/`last` (18%), null/empty fields (4%), shared frame table (23%): triage 23.2 KB -> 12.6 KB (-46%).
4. **Prompt caching costs more than it saves** here: each step uses a different model (caches are per model), the triage prefix is under the 512-token minimum, analysis is one call per run (1.25x write never read). Keep `cache_control` only on escalation and retries.
5. **Cache prices** are 0 in the example config, so cost reads low when caching applies: require them or derive them (0.1x read, 1.25x write).
6. **No per-run reservation**: one run can overshoot the cap by ~30%; skip escalation when `today + estimate > cap`. `max_input_tokens.escalate` is never enforced.
7. **Batch API** (-50% on every token) fits a nightly job but needs a two-phase run (submit, collect on the next trigger); worth it at fleet scale.
8. Research R3 note to correct: Sonnet 5.5 cache reads are 0.1x, not 0.05x; escalation does not reuse the analysis prefix when the model differs.

## Architecture and maintainability

Good: exactly four justified contracts; everything else `final`; validated value objects; PSR-20 clock; the redaction
allowlist type; loud, specific failure handling; contract suites over every store and source without network.

Debt, in the order to pay it:
1. `Watcher::locked()` is ~250 lines and ~30 branches, with hidden mutable state (`$pendingWrites`, `$deployInfo`) on a Laravel singleton; the "dependencies -> snapshot -> run record" tail is copied 5 times. Extract a concrete `RunLedger` (`defer()`, `finish()`), an `EventCollector` (read + reduce + rule/mute hits + truncation), then private `analyze()` / `buildDigest()`. No generic pipeline interface (Principle VIII).
2. Config: validators do not return defaults, so `Factory` re-applies them (Datadog site, PDO table, Redis host/port/db); ~35 untyped `$c->section['key']` reads. Return filled arrays; array-shape PHPDoc; PHPStan 2 at level 9.
3. Duplication that is a **privacy hazard**: placeholder names in `Normalizer::SKIP` and `Redactor::RESERVED`; the file-extension list in `Normalizer` and `SlackText`. One constant each.
4. Dependency cycle Privacy <-> Analyze (`Redactor` uses `Finding`): move `redactFinding` into the analyzer decorator; move `Budget::truncate` to Select.
5. `DigestData` has 25 positional constructor arguments, `RouterSettings` 11: named arguments.
6. Dead or speculative code: `source.sample_size` (validated, documented, never read); a per-dependency source resolver closure while per-dependency sources are rejected; a 30-line anonymous `StateStore` only to defer writes; `GroupStatusLabel` duplicates `GroupStatus`; `Keys::ttl(SPEND, 0, 0)` dummy arguments; `exhausted:` key bypasses `Keys`; Redis store takes a clock it discards.
7. Tests: move exact Slack text to golden files; add Infection on `Normalizer`, `Redactor`, `Selector`, `ModelRouter`, `Budget`, `MuteList`, `BudgetAlerts`, `OutputValidator`, `RunGate`.
8. Release readiness: `.gitattributes` export-ignore (tests, specs, `.specify`, `.claude`), `.editorconfig`, `extra.laravel.providers`, PHP 8.5 in CI, `illuminate ^12`, a `composer ci` script, a first tag, a clearer `bin/watcher` autoload error.

## Features to make the package more useful

Ordered by value for the SEQ services (orders-api + two BFFs) and by effort.

**Coverage: see more of what actually breaks**
1. **Fleet mode**: one process, several service configs, shared state and budget; one digest per service or one combined digest. The BFFs have no CLI or scheduler, so this is how they get watched at all (see rollout).
2. **Cross-service correlation**: the BFFs call `orders-api` for most endpoints; when BFF errors referencing `orders-api` rise in the same window as orders-api errors, say so in one finding instead of three. Builds on the dependency context.
3. **Kubernetes events source** (roadmap 003): CrashLoopBackOff, OOMKilled, probe failures, HPA errors. Half of the hand-made `dev-notes` backlog is pod-level and invisible in app logs.
4. **Deploy-triggered run**: after a release (`WATCHER_RELEASE` changes), compare the hour after with the same hour before and report regressions within an hour of the deploy instead of the next morning.
5. **On-demand incident run**: `watcher run --since=2h --service=orders-api` prints "what changed in the last 2 h" to stdout or a thread.
6. **Better baseline**: 7-day rolling and same-weekday comparison instead of "yesterday only"; fewer false "grown" on Mondays and fewer re-baselines.
7. **Template quality**: Drain-style similarity clustering instead of exact token-count clusters (fewer `<*> <*> <*>` templates); optional use of the Loki patterns API / Datadog patterns.
8. **Metrics and traces**: Prometheus error-rate and latency deltas; Sentry issues; trace ids (the BFFs already add `traceId`) turned into Tempo/Datadog APM links.
9. **Code-aware analysis** (roadmap 002, approved): read the top frames' code at the deployed commit for a real root-cause hypothesis.

**Workflow: from finding to action**
10. **Known-issue memory**: map a fingerprint to a Jira key (`ABC-123`); the digest shows "known: ABC-123" and stops re-analysing it (cheaper, less noise). Read-only Jira search to suggest existing tickets.
11. **Ticket drafts**: a ready-to-paste Jira description per finding (title, evidence, counts, links), optionally created by a separate opt-in command (writes need a constitution amendment).
12. **Slack threads and interactivity** (needs a bot token): one thread per finding with "still happening (+N)" updates instead of a new digest line; buttons for mute 7d / acknowledge / create ticket; thumbs up/down as quality feedback.
13. **Severity routing**: critical findings to a separate channel or an on-call mention; quiet days produce nothing.
14. **More notifiers**: generic webhook, Microsoft Teams, e-mail, GitLab issue.
15. **Weekly report**: top recurring problems, newly fixed (disappeared after a release), cost per service, noisiest log sites.

**Hygiene: make the services better**
16. **Log-privacy lint**: watcher sees raw lines locally, so it can count pattern hits (emails, tokens, names-in-clusters) per log template and frame **without sending them**, and report "`AuthService.php:118` logs user data at ERROR" to the owning team. The survey already found three such sites (see below).
17. **Log-quality report**: log sites with stack traces in the message, unbounded lines, high-volume INFO, stderr access-log noise; proposals for `mute`/`watch_rules` from observed data.
18. **Cost dashboard**: per service and day, tokens and spend, from the state store (or the `--json` lines).

Writes to monitored systems (Grafana annotations, Jira tickets, Slack buttons that change state) are excluded by
Principle II; each needs an explicit constitution amendment first.

Backend: environments differ. Start with the environment whose logs are in **Loki/Grafana** (owner's choice); the
Datadog environments (`int`, query `service:orders-api env:int kube_namespace:example-ns`) come second, because the Datadog
source is the least verified against a live API. The Loki labels for orders-api and the BFFs still have to be confirmed
(Grafana label browser or the Grafana MCP once its key works).

Watcher-relevant traps found in the services:
- Several formats share one stream: Monolog lines, nginx/php-fpm access logs (tagged `status:error` from stderr in Datadog), supervisord, raw PHP fatals with multi-line frames, BO audit JSON. Use the Monolog level in the text, mute access lines, exclude the audit logger.
- The Monolog channel is `APP_ENV`, which is `local` on int: not usable as an environment tag.
- BFF `run.sh` can print the whole environment (incl. `DB_PASSWORD`) to stdout with an empty `.env`: add an `extra_patterns` entry for `KEY=value` lines and fix the script.
- `AppVersion.php` only parses strict `X.Y.Z`; read `app/.version` or the image tag instead.
